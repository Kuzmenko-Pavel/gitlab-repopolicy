# Розробка gitlab-repopolicy

Почніть з [архітектури](architecture.md), щоб зрозуміти джерело чинних політик, послідовність перевірок і межі відповідальності ядра та модулів. Після цього [керівництво розробника](development.md) допоможе підготувати інструменти й запустити локальні перевірки через Makefile.

Для зміни політики спершу прочитайте її [користувацький довідник](../README.md#користувачам-політик) і відповідні сценарії. Публічні схеми PATHPOLICY та TAGPOLICY `version: 1`, коди відмов і формат audit є контрактами; документаційна зміна не є підставою їх змінювати.

## Перевірка внеску

[CONTRIBUTING](../../CONTRIBUTING.md) визначає коміти, DCO та review. Обов'язкові перевірки - `make code-lint test-unit test-integration`; зміни ідентичності, API-клієнта чи встановлення також потребують `make test-e2e`. Як працюють корпус, виконувані приклади документації та GitLab-стенд, пояснює [розділ про тести](development.md#тести).

Мейнтейнерам, які готують підписаний тег і артефакти, потрібне [керівництво релізу](release.md). Налаштування робочого інстансу й аварійні процедури описано окремо в [адміністративній документації](../README.md#адміністраторам-gitlab).
